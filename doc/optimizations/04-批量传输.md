# CentralCache → ThreadCache 批量传输问题

## 问题概述

当前项目中 CentralCache 向 ThreadCache 分发内存块时，每次只传输 **1 块**，而非真正的 TCMalloc 那样**批量传输多块**。ThreadCache 中的相关代码（遍历链表、计数 `batchNum`）是为此预留的，但目前等于白跑。

## 当前实际行为

### 传输路径

```
ThreadCache::fetchFromCentralCache(index)
    │
    ▼
CentralCache::fetchRange(index)
    │
    ├── centralFreeList_ 有货？
    │   └── YES → 取链表头 1 块
    │            *reinterpret_cast<void**>(result) = nullptr  ← 断开，next 置空
    │            返回单块
    │
    └── NO → 从 PageCache 拿 Span，切成 blockNum 块
             *reinterpret_cast<void**>(result) = nullptr  ← 断开第一块，next 置空
             剩余块挂在 centralFreeList_（CentralCache 自己内部）
             返回单块
```

### 关键代码

```cpp
// CentralCache.cpp fetchRange (两处相同模式)
*reinterpret_cast<void**>(result) = nullptr;     // 断开
centralFreeList_[index].store(next, ...);         // 剩余留在 CentralCache
return result;                                     // 只返回单块
```

### ThreadCache 侧

```cpp
void* ThreadCache::fetchFromCentralCache(size_t index)
{
    void* start = CentralCache::getInstance().fetchRange(index);
    // start = 单块，start->next 永远是 nullptr

    freeList_[index] = *reinterpret_cast<void**>(start);  // 永远是 nullptr
    // batchNum 遍历永远是 1
    return result;
}
```

### 时序对比

```
当前（单块传输）:
  allocate #1 → fetchRange (锁1次, 拿1块)
  allocate #2 → fetchRange (锁1次, 拿1块)
  ...
  Cross-layer calls = N

真正的 TCMalloc（批量传输）:
  allocate #1 → fetchRange (锁1次, 拿8块, 7块进ThreadCache)
  allocate #2 → 命中 ThreadCache 本地
  ...
  allocate #8 → 命中 ThreadCache 本地
  allocate #9 → fetchRange (锁1次, 拿8块)
  Cross-layer calls = N / 8
```

## 修改方案

### 方案 A：修改 CentralCache::fetchRange 返回链表（推荐）

fetchRange 从 centralFreeList_ 取前 BATCH_SIZE 个节点，断开第 BATCH_SIZE 个的 next，返回这段链表的头。

### 方案 B：在 ThreadCache 侧循环调用

不改 CentralCache，fetchFromCentralCache 中循环调 fetchRange N 次，自己串链表。缺点：每次循环都要加锁/解锁。

## 影响评估

| 维度 | 当前 | 改为批量 |
|:---|:---|:---|
| 跨层调用频率 | N | N / BATCH_SIZE |
| 自旋锁竞争 | 频繁 | 大幅减少 |
| CentralCache 链表遍历 | 每次取 1 块 | 每次取 BATCH_SIZE 块 |
